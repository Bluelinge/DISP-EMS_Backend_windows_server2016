# DISP-EMS 开发交接与续开发手册

> 更新日期：2026-10-14  
> 适用仓库：`https://github.com/Bluelinge/DISP-EMS_Backend.git`  
> 本文用于在另一台 Windows 开发机继续开发、在 Ubuntu 22.04 x86_64 服务器离线部署，以及定位日常运行问题。

---

## 1. 当前交付状态

系统已从纯前端原型扩展为可容器化运行的内部生产系统：

- 前端：Vue 3 + Vite + Pinia + Element Plus，操作端与管理端共用一个 SPA。
- 后端：JDK 8、Spring Boot 2.7.18、MyBatis-Plus、Maven。
- 数据：MySQL 5.7、Redis 7、MinIO（私有对象存储）。
- 部署：Docker Compose；业务页面统一经 `http://服务器IP:8089` 访问。
- 数据库迁移：Flyway，迁移文件在 `server/src/main/resources/db/migration/`。
- API：统一前缀 `/api/v1`；生产环境由 Web 容器反向代理至后端。

已接入的主要业务包括：认证/改密/人员、工位、工艺与步骤、任务作业/确认/汇总、任务与生产统计、视频分类与资源、文件上传、投影图标与模板、任务 SSE 事件。

### 必须先知道的状态

1. 当前工作区有**大量未提交改动**，包括 `server/`、`deploy/`、`docker-compose.yml`、`src/api/` 和多个页面文件；换电脑前必须提交并推送，或完整复制整个工作区。
2. `deploy/.env`、离线镜像目录和离线 `.tar` 均被 Git 忽略，**不会随 Git 推送**。它们需单独备份/复制。
3. 本文编写时本机 Docker Desktop 未运行，因此不能以当前机器的容器状态作为服务已启动的依据。启动 Docker Desktop 后按第 4 节启动并检查。
4. 未发现 `server/src/test/` 自动化测试目录。后续修改关键流程时，应先按第 6 节做人工回归，并补齐单元/集成测试。

## 3. 换电脑后的首次准备

### 3.1 必需软件

Windows 开发机建议安装：

- Git
- Node.js 22（使用仓库的 `package-lock.json`）
- JDK 8（后端编译目标为 Java 8）
- Maven 3.8+（或 IDE 内置 Maven）
- Docker Desktop，启用 Linux containers / WSL 2
- 可选：IntelliJ IDEA、VS Code、Navicat

### 3.2 获取代码与恢复本机配置

```powershell
git clone https://github.com/Bluelinge/DISP-EMS_Backend.git
cd DISP-EMS_Backend
git status
npm ci
```

在旧电脑安全复制以下文件到新电脑（不要提交到 Git，也不要发到公开位置）：

```text
deploy/.env                         本地服务密码、访问地址、初始账号配置
deploy/disp-ems-ubuntu22-x86_64-offline.tar   已生成的 Linux 离线包（如需要）
```

若没有旧的 `deploy/.env`，执行：

```powershell
Copy-Item deploy/.env.example deploy/.env
```

然后至少修改 `MINIO_PUBLIC_ENDPOINT` 与 `PUBLIC_ORIGIN` 为浏览器实际可访问的地址。仅本机联调时可保留 `localhost:8089`；局域网手机/工位机访问时要加入实际 IP，例如：

```properties
MINIO_PUBLIC_ENDPOINT=http://192.168.1.10:9000
PUBLIC_ORIGIN=http://192.168.1.10:8089,http://localhost:8089,http://127.0.0.1:8089
```

> 不要把真实的 `.env`、数据库备份、MinIO 对象或离线镜像提交到 Git。

### 3.3 恢复未提交源码（非常重要）

在旧电脑执行并确认：

```powershell
git status
git add .
git commit -m "feat: complete DISP-EMS backend and offline deployment"
git push origin main
```

如暂时不能提交，使用压缩包完整复制项目目录，但不要带上 `node_modules/`、`dist/`、`server/target/`。新电脑仍执行 `npm ci` 和 Maven 构建来恢复依赖。

若需要连同业务数据迁移，不能只复制源码：还需要迁移 Docker 卷 `mysql_data`、`redis_data`、`minio_data`，或分别导出 MySQL 与 MinIO 数据，见第 8 节。

## 4. 本机完整启动、停止与检查

### 4.1 推荐：Docker Compose 一键联调

先启动 Docker Desktop，确认以下命令有版本输出：

```powershell
docker version
docker compose version
```

在项目根目录执行：

```powershell
docker compose --env-file deploy/.env up -d --build
docker compose --env-file deploy/.env ps
```

正常服务及端口：

| 服务 | 容器名 | 用途 | 主机端口 |
|---|---|---|---|
| web | `disp-ems-web` | 前端、API 反代 | `8089` |
| server | `disp-ems-server` | Spring Boot API | 仅容器网络 |
| mysql | `disp-ems-mysql` | MySQL 5.7 | `127.0.0.1:3307` |
| redis | `disp-ems-redis` | 会话、事件 | 仅容器网络 |
| minio | `disp-ems-minio` | 私有对象存储 | `9000`、`9001` |

页面入口：`http://localhost:8089`  
MinIO 控制台：`http://localhost:9001`

查看日志：

```powershell
docker compose --env-file deploy/.env logs -f server
docker compose --env-file deploy/.env logs -f web
```

停止但保留容器与数据：

```powershell
docker compose --env-file deploy/.env stop
```

重新启动：

```powershell
docker compose --env-file deploy/.env start
```

移除容器和网络、但保留 MySQL/Redis/MinIO 数据卷：

```powershell
docker compose --env-file deploy/.env down
```

**禁止在需要保留数据时使用 `docker compose down -v`**；`-v` 会删除业务数据卷。

### 4.2 前后端单独调试

前端开发服务器会将 `/api` 代理到 `http://127.0.0.1:8080`：

```powershell
npm run dev
```

后端需要可用的 MySQL、Redis、MinIO；可通过 Compose 仅启动基础组件后，在新终端运行：

```powershell
docker compose --env-file deploy/.env up -d mysql redis minio
cd server
mvn spring-boot:run
```

后端配置可通过环境变量覆盖，关键变量为：

```text
DISP_DB_URL / DISP_DB_USERNAME / DISP_DB_PASSWORD
DISP_REDIS_HOST / DISP_REDIS_PORT / DISP_REDIS_PASSWORD
DISP_MINIO_ENDPOINT / DISP_MINIO_PUBLIC_ENDPOINT
DISP_MINIO_ACCESS_KEY / DISP_MINIO_SECRET_KEY / DISP_MINIO_BUCKET
DISP_BOOTSTRAP_ADMIN_NO / DISP_BOOTSTRAP_ADMIN_NAME / DISP_BOOTSTRAP_ADMIN_PASSWORD
DISP_FFPROBE_PATH
DISP_CORS_ALLOWED_ORIGINS
```

前端 API 模式由环境变量控制：

```text
VITE_USE_MOCK=false
VITE_API_BASE_URL=/api/v1
VITE_API_PROXY_TARGET=http://127.0.0.1:8080
```

`src/api/request.js` 已为局域网 HTTP 环境提供幂等键降级实现，避免 `crypto.randomUUID()` 在非安全来源不可用时导致“请求失败”。不要直接删掉该兼容逻辑。

## 5. 账号、权限与密码

### 本地 Compose 的首次管理员

管理员由 `deploy/.env` 中的以下变量决定：

```properties
BOOTSTRAP_ADMIN_NO=ADMIN-001
BOOTSTRAP_ADMIN_NAME=系统管理员
BOOTSTRAP_ADMIN_PASSWORD=... 
```

初始管理员只在空数据库初始化时创建。数据库已有用户后，改 `.env` 不会重置旧账号密码；请用管理端人员管理或数据库维护方式处理。

### Ubuntu 一键离线包的首次账号

离线安装器首次创建 `app/.env` 时，按照当前现场约定固定为：

| 项目 | 值 |
|---|---|
| 初始超级管理员工号 | `ADMIN-001` |
| 初始超级管理员密码 | `dispadmin` |
| MySQL 应用密码 | `dispadmin` |
| MySQL root 密码 | `dispadmin` |
| Redis 密码 | `dispadmin` |
| MinIO root 密码 | `dispadmin` |

已存在的 `app/.env` 不会被安装器覆盖。虽然现场约定使用固定密码，正式投产后仍建议由受控人员修改，并同步更新相应服务配置；不可只改其中一个服务的密码。

## 6. 续开发与回归重点

### 6.1 业务关键链路

每次改动后至少人工验证：

1. 管理员登录、退出、个人资料改密；修改后用新密码重新登录。
2. 新建/编辑人员，分别验证操作员与管理员权限、工位登录。
3. 工位管理变更识别模式后刷新操作端，确认识别方式变化。
4. 上传视频、等待处理状态完成、查看播放、绑定到工艺步骤，再在操作端确认视频可见。
5. 新建/编辑投影模板及步骤投影元素，在操作端刷新或新建任务后确认投影变化。
6. 工艺步骤编辑后，在新任务中确认步骤内容更新；进行中的任务使用创建时快照是预期行为。
7. 使用同一钢印号跨工位完成任务，确认后续工位可以接续；需要重新录入产品编码的工位应重新建立产品编码与钢印号绑定。
8. 填写每个带参数的步骤，完成全部工位后到大汇总确认参数均出现；再检查任务记录与生产统计。
9. 单投影屏与无投影屏情况下均可创建任务；投影不可用不应阻断任务创建。
10. 刷新页面后确认登录态、管理资源、视频签名 URL、任务快照可正常恢复。

### 6.2 代码修改边界

- 数据库结构只通过新增 Flyway 迁移完成，绝不修改已在线上执行过的 `V1~V5`。
- 写接口应携带 `Idempotency-Key`；根资源更新应传递/校验 `expectedVersion`。
- MySQL 目标版本为 5.7，避免 MySQL 8 专用 SQL、窗口函数与依赖 `CHECK` 约束的校验。
- 文件二进制放 MinIO；关系、对象键、摘要、状态等元数据放 MySQL。不要把 MinIO 配置成公开桶。
- 视频播放需通过后端短期签名 URL；不要把 `blob:` 地址或 Base64 长期保存到前端状态。
- 任务与投影 SSE 只是实时通知，重新进入/断线后必须以 API 的任务或投影快照为准。
- 管理端任务记录使用服务端分页；时间筛选参数 startedFrom / startedTo 是 YYYY-MM-DD 自然日，按 Asia/Shanghai 转换为 UTC 查询边界，型号筛选使用 GET /tasks/models 返回的选项。
- 视觉调整遵循 `docs/04-设计系统使用规范.md`，不要整体替换 `src/design/` 的设计系统副本。

### 6.3 常见故障定位

| 现象 | 优先检查 |
|---|---|
| 页面提示“请求失败” | 浏览器 Network 是否发出 `/api/v1` 请求；`web`、`server` 日志；访问地址是否已经写入 `PUBLIC_ORIGIN` |
| 跨局域网操作时创建任务失败 | 前端是否保留 `request.js` 的幂等键兼容逻辑；确认实际页面端口是 `8089` |
| 登录/改密失败 | 检查访问的是 API 模式而非 Mock；看 `server` 日志；确认数据库账号记录和当前密码一致 |
| 视频上传/播放失败 | 查看 `server` 日志、MinIO `9000` 可达性、`MINIO_PUBLIC_ENDPOINT` 是否为浏览器可达 IP；检查文件处理状态 |
| 管理端资源加载失败 | 查看后端日志和浏览器 Network；检查 token 是否过期、CORS 的 `PUBLIC_ORIGIN` 是否包含实际协议/主机/端口 |
| 数据未出现 | 用 Navicat 连 `127.0.0.1:3307`，数据库名、用户和密码见 `deploy/.env`；确认未连到旧环境 |

## 7. Ubuntu 22.04 x86_64 离线部署

生成好的交付包路径（该文件被 Git 忽略，需单独拷贝）：

```text
deploy/disp-ems-ubuntu22-x86_64-offline.tar
```

目标服务器要求：Ubuntu 22.04、`x86_64`、systemd、root 或 sudo；防火墙允许车间访问 TCP `8089`。若需要直接管理 MinIO，再放行 `9000/9001`。

```bash
mkdir -p /opt/disp-ems-offline
tar -xf disp-ems-ubuntu22-x86_64-offline.tar -C /opt/disp-ems-offline --strip-components=1
cd /opt/disp-ems-offline
sudo bash install.sh --host 192.168.1.10
```

脚本会在 Docker 不可用时安装包内附带的 Docker Engine 和 Compose 插件；如果已有正常 Docker，会直接复用，不会停止其他容器。DISP-EMS 使用 Compose 项目名 `disp-ems`，默认仅占用 `8089`（以及 MinIO 的 `9000/9001`）。安装前确认端口未被占用：

```bash
docker --version
docker compose version
ss -lntp | grep -E ':8089|:9000|:9001'
```

安装后日常运维：

```bash
cd /opt/disp-ems-offline
docker compose --project-name disp-ems --env-file app/.env -f app/docker-compose.yml ps
docker compose --project-name disp-ems --env-file app/.env -f app/docker-compose.yml logs -f server
docker compose --project-name disp-ems --env-file app/.env -f app/docker-compose.yml stop
docker compose --project-name disp-ems --env-file app/.env -f app/docker-compose.yml start
docker compose --project-name disp-ems --env-file app/.env -f app/docker-compose.yml down
```

`down` 不会删除数据；严禁在有业务数据时使用 `down -v`。

如需重新生成离线包（构建机必须能联网、Docker 可用，且已完成本地验证）：

```powershell
.\deploy\build-linux-ubuntu22-x86_64-offline.ps1
```

该脚本会重新下载 Docker 静态包、Compose 和 Ubuntu 运行依赖，并导出当前构建机的应用镜像。因此不能在无网机器上重新打包。

## 8. 数据查看、备份与迁移

### Navicat 查看本地数据库

连接参数从 `deploy/.env` 读取。默认连接方式：

```text
主机：127.0.0.1
端口：3307
数据库：disp_ems
用户名：disp_ems
密码：MYSQL_PASSWORD 的值
```

宿主机仅绑定 `127.0.0.1:3307`，因此 Navicat 应在部署服务器本机运行；不要为了远程连接而随意暴露数据库端口。确有运维需求时建议通过 SSH 隧道。

### 推荐备份

至少分别备份：

1. `deploy/.env` 或现场 `app/.env`（加密保管）。
2. MySQL 逻辑备份：`mysqldump` 导出的 SQL。
3. MinIO 数据卷/对象（上传的视频、图标、Excel 等）。
4. Docker 数据卷：`mysql_data`、`redis_data`、`minio_data`。

在有短暂停机窗口时，最稳妥的是停止 DISP-EMS 后再归档 Docker 卷；恢复到另一服务器时也必须一起恢复 MySQL 与 MinIO，否则数据库内的文件元数据会指向不存在的对象。
