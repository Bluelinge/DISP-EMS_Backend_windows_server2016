# 02 · 接口契约（API Contract）

> 目标：让前端**尽量只改 `src/store.js` 一个文件**即可完成后端对接。
> 本文档把 store 里每一个 action 的语义、入参、出参、以及建议的 HTTP 接口逐条列出。
> 字段含义与枚举取值见 `docs/03-数据模型与枚举.md`。

---

## 当前工艺范围值接口

当前实现使用 `POST /api/v1/processes` 创建或替换型号工艺，以及 `PATCH /api/v1/processes/{id}/steps/{stepNo}` 修改单步；两者在写入前统一校验 `type: 2` 参数的 `referenceValue`。

新格式为单行 `(>x),(=x),(=y),(<y)`，空段必须写 `()`。包含下限必须同时填写同值的 `(>x)` 与 `(=x)`；包含上限必须同时填写同值的 `(=y)` 与 `(<y)`。至少填写一个边界，不能产生空区间。支持带符号整数和小数，保存时去除空格并规范化数值；旧两行最小/最大值仍可提交并规范化为等价闭区间。

非法定义返回 HTTP 422、业务码 `1007`，错误消息包含步骤号、参数编号和具体边界或格式原因。读取工艺不改写原始参考值；新任务冻结当前工艺，已有任务的 `referenceValue` 快照不变。实际测量值超限或非数值仍可记录，由管理端统计判为偏离。

## 1. 改造方式（推荐三步）

**第一步：拆成两份实现，用环境变量切换**

```
src/store.mock.js   ← 把现有 store.js 的实现原样搬过来（localStorage 版，离线自测用）
src/store.api.js    ← 新建，HTTP 版
src/store.js        ← 只做分发：import.meta.env.VITE_USE_MOCK ? 用 mock : 用 api
```

`.env.development` / `.env.production` 里指定 `VITE_USE_MOCK=true|false`。

> 好处：后端接口没就绪时前端能继续对着界面自测；接口逐步就绪时**一个 action 一个 action 地替换**，随时可回退。

**第二步：加统一请求层**（`src/api/request.js`）
需处理：baseURL、token 注入、统一错误码 → `ElMessage` 提示、loading、超时重试。
现有代码里所有 `ElMessage.warning/error/success` 的文案可作为提示文案基线。

**第三步：按下方总览表逐条替换。**

## 3. 逐条详细契约

### 3.1 认证

#### `loginByCredentials(no, password)`
- **入参**：`no` 工号字符串（需 `trim`）、`password` 明文
- **出参（现原型）**：`'operator' | 'admin' | null`（null = 失败）
- **现行为**：按工号精确匹配未被删除的人员；**仅允许 `status === '在岗'` 的人登录**；密码明文比对（原型无加密）；成功后写入 `role` / `operatorName` / `currentUserId`
- **建议接口**：`POST /auth/login` → `{ token, user: { id, no, name, role, dept, phone, status } }`
- **后端注意**：角色到端口的映射是 `role === '操作员' ? 'operator' : 'admin'`（**管理员 / 超级管理员都进管理端**）。建议后端直接返回 `port: 'operator' | 'admin'`，避免前端硬编码角色名。
- **失败提示**（现文案）：`工号或密码不正确，请重新输入`

#### `updatePersonPassword(id, password)`
- 登录人自助改密。原型在 `UserProfileDialog.vue` 里做校验：原密码必须匹配、新密码 ≥ 6 位、两次一致、不得与原密码相同。
- **建议**：改密属敏感操作，后端务必**在服务端重新校验原密码**，不要信任前端校验结果。

#### `resetPersonPassword(id)`
- 管理员重置：原型生成 `MES@{工号后4位}`。**若后端有规则请以后端为准**。

### 3.2 工艺

#### `activateProcess(id)` → `boolean`
- 把 `processFiles` 里指定工艺设为"当前工艺"，同步写入 `processRecord`、`processSteps`、`stepProjection`、以及展示用的 `title/version/sourceWorkbook/sourceDocument`。
- **建议接口**：`POST /processes/{id}/activate`，返回激活后的完整工艺对象（省一次详情请求）。

#### `importProcess(payload)`
- **入参**：`{ model, title, version, sourceWorkbook, sourceDocument, steps[] }`（由前端解析 Excel 得到，见 `src/data/process.json` 结构）
- **现行为**：**同型号覆盖** —— 若已存在同 `model` 的工艺则复用其 id 并整体替换；否则新建 `P-{8位时间戳}`。导入后自动把新工艺设为当前工艺，并给每个工序绑定默认模板 `T-001` 的投影元素。
- **建议接口**：`POST /processes/import`（请求体同上）
- **后端注意**：
  - 步骤可带可选字符串 `content`（操作步骤详情）；Excel 表头“步骤内容”映射到该字段。旧 Excel 缺少该列时按空字符串导入。步骤里的 `sourceRow`（Excel 行号）与 `sourceTypeMissing`（参数类型缺失标记）是**导入预检**的依据，请务必落库。
  - 原型在导入弹窗里展示了"预检结果"（原 Excel 有 22 处参数类型留空），若后端做解析，需返回逐行错误列表。
  - 参数类型支持 `0` 手动输入、`1` 单选、`2` 范围值；新范围值的 `referenceValue` 使用四段逗号格式 `(>x),(=x),(=y),(<y)`，允许 `()` 表示空边界，旧两行数值闭区间格式继续兼容。
  - Excel 的 `视频名称` 必须能唯一匹配有效视频资源；匹配忽略常见视频扩展名、路径、首尾空格与大小写差异，写入时保存视频资源的标准 `name`。找不到或存在多个候选时返回来源行错误，不导入该工艺。

#### `updateStep(stepNo, value)`
- 修改步骤定义（标题 / 步骤内容 / 是否重要工序 / 关联视频 / 参数等）；读取旧步骤时缺失的 `content` 按空字符串兼容。
- **约束**：**不得改写在制任务的快照**（见 3.3 `startTask`）。

#### `applyTemplate(stepNo, templateId)` / `updateProjection(stepNo, elements)`
- 前者把整份模板的 `elements` 复制到某工序；后者直接覆盖某工序的投影元素数组。
- **注意**：是**深拷贝**语义，之后修改模板不会反向影响已套用的工序。

### 3.3 任务（工位作业）

#### `startTask()` → `taskId | null`
- **前置**：必须有可用工艺（`processAvailable`）。
- **生成任务对象**（字段见 `docs/03`），关键点：
  - 以 `steelNo` 查找在制任务集合：同一钢印号再次录入（即使扫码产品编码不同）必须恢复原任务和原步骤进度；其它钢印号的在制任务不得覆盖或中断；产品型号不一致应拒绝恢复。
  - 产品编码变化时写入 `productCodeAudit`，更新该钢印号的当前产品编码映射，不得新建第二条任务。
  - `processSnapshot`：**冻结当前完整工序快照**。之后管理端编辑工艺**不会**改写在制任务 —— 这是原型明确承诺的行为，后端必须保证同样的隔离。
  - `projection`：冻结各工序的投影配置。
  - `logs: {}`：以 `stepNo` 为键的步骤完成记录。
  - `status: '进行中'`、`currentStepIndex: 0`。
- **建议接口**：`POST /tasks` → `{ id, processSnapshot, projection, startedAt, ... }`

#### `recordStep(values = {})` → `boolean`
- 提交**当前步骤**：写 `logs[stepNo] = { stepNo, title, actionCode: 0, values, time }`，并把 `currentStepIndex + 1`。
- `values` 形如 `{ 1: '21', 2: '55', 3: '不得有明显落灰' }`（键 = 参数的 `index`，值 = 操作员录入/选择的文本）。
- **建议接口**：`POST /tasks/{taskId}/steps`，body `{ stepNo, values }`。建议后端服务端复核必填与参数定义；范围值允许记录超限或非数值实际值，作为后续参数偏离统计依据，不应拦截记录。

#### `jumpToStep(next)` → `void`
- 跳步。**向前跳会补写跳过记录**：中间未完成的步骤写入 `actionCode > 0` 的日志（`actionCode: step.importance ? 2 : 1`），即"重要工序跳过"与"普通工序跳过"可区分。
- **建议接口**：`POST /tasks/{taskId}/jump`，body `{ toIndex, skipped: [{ stepNo, actionCode }] }`，并**要求后端写审计日志**。
- **业务约定**：跳步**只在审计日志里留痕**（页面上有明确提示）。

#### `completeTask(items)` → `void`
- **入参**：`items` = 完成确认表单的数据（由 `completionItems()` 组装，见下）。
- **现行为**：写入 `completionForm`（`{ savedAt, operatorName, items }`），把任务 `status` 改为 `已完成`、写 `endedAt` 与 `durationSec`（秒，由 `startedAt` 差值算），并同步进 `taskHistory`。
- **⚠️ `durationSec` 是前端算的**，接后端时应改为**服务端用开始/结束时间计算**，避免客户端时间不可信。
- **状态机**：`进行中` → `已完成`。取消完成表单不会改状态（仍为进行中）。

#### `completionItems()` → `Array` ⚠️
- 由 `completedLogs` × 工序的 `parameters` 组装：
  ```js
  [{ stepNo, title, parameters: [{ ...param, operatorValue }] }]
  ```
- 建议后端提供：`GET /tasks/{taskId}/completion-form`。

#### 计算属性（建议后端返回）
| 名称 | 含义 |
|---|---|
| `steps` | 当前工艺全部工序 |
| `activeSteps` | 当前任务的工序序列（来源 `task.processSnapshot`，无任务时取 `processSteps`） |
| `currentStep` | 当前步骤对象 |
| `completedLogs` | 已完成步骤日志（`actionCode === 0`） |
| `auditLogs` | 跳步/异常日志（`actionCode > 0`） |
| `processAvailable` | 是否存在可用工艺（决定能否开始任务） |
| `sourceMissingCount` | 参数类型缺失的工序数（导入预检用） |
| `defaultTemplate` | `isDefault === true` 的模板（即 `T-001`） |

### 3.4 视频分类

#### `createVideoCategory({ name, parentId })` / `renameVideoCategory(id, name)` / `deleteVideoCategory(id)`

- 分类实体为 `{ id, name, parentId, sortOrder }`；`parentId: null` 是一级分类，最多两级。
- 新增或重命名时，同一级名称不可重复；新增二级分类时其父级必须是一级分类。
- 删除不级联：一级分类含二级项时禁止删除；任意分类仍被有效视频引用时禁止删除。
- 视频使用 `categoryId` 关联分类，可直接关联一级分类或二级分类；工艺步骤继续用 `videoName` 绑定视频，并按“一级分类 → 二级分类 → 视频”三级联动选择。一级分类没有二级项时，二级步骤显示“未细分（直接归类）”。
- 上传视频前按标准视频名检查有效资源；标准名忽略常见视频扩展名、路径、首尾空格及大小写。发生重名时由客户端确认“替换上传”或“取消上传”；替换复用原视频 `id`，更新媒体、名称与分类，以保持已有工艺绑定有效。
- **建议接口**：`GET /video-categories`、`POST /video-categories`、`PATCH /video-categories/{id}`、`DELETE /video-categories/{id}`；视频查询及上传请求携带 `categoryId`。

### 3.5 通用资源删除

#### `deleteResource(type, id)` → `{ ok, message }`
- `type` 取值：`processes` / `videos` / `templates` / `icons` / `dicts` / `people`（对应 `state.deleted` 的同名数组）
- **现行为（逻辑删除 + 引用预检）**：
  - 不支持的类型 → `{ ok:false, message:'不支持删除该资源' }`
  - 不存在 → `'资源不存在或已被删除'`
  - 已删除 → `'资源已被删除'`
  - `templates` 且是默认模板 → `'默认模板不可删除，只能编辑'`
  - 删除**当前工艺**时会自动回退到另一份可用工艺
- **产品要求**：删除前**必须展示引用数量**（"引用预检"弹窗），由前端调一个预检接口拿引用计数，用户确认后才真正删。
- **建议接口**：`GET /{resource}/{id}/references` + `DELETE /{resource}/{id}`

#### `saveIconAsset({ originalName, name, dataUrl })`
- 上传投影图标素材（PNG）。`iconNames` 是内置图标名列表，`customIcons` 存用户新增。
- **建议**：改为标准文件上传 → 后端返回 URL，前端不再存 `dataUrl`（现在存 base64 会让 localStorage 迅速膨胀）。

### 3.6 投影模板

#### 浏览器副屏投影
- `openProjectorWindow(taskId, screen?)` 复用固定命名投影窗口；传入已配置屏幕时按其可用工作区的 `left/top/width/height` 定位并铺满。
- 投影屏偏好仅写入当前浏览器 `localStorage`，不属于任务、工艺或投影模板数据；可通过 `getScreenDetails()` 获取屏幕列表并在浏览器拒绝权限、缺少副屏或不支持 API 时降级为普通窗口。
- 运行要求：Chrome/Edge Chromium 与安全上下文（HTTPS 或本机 `localhost`）；浏览器地址栏和窗口边框仍由浏览器控制。

#### `addTemplate(name)` → 新模板 id
- 新建模板，默认 `width: 1920, height: 1080`（**投影画布尺寸固定**）。
- **建议接口**：`POST /projector/templates`

#### `canDeleteTemplate(id)` → `boolean`
- 默认模板（`T-001`）不可删除。这是纯前端判断，**后端也要做同样校验**。

## 4. 需要后端配合补齐的字段

原型有几处"能用但不够严谨"，建议后端接手时修正：

| 位置 | 现状 | 建议 |
|---|---|---|
| `durationSec` | 前端用 `Date.now()` 差值计算 | 服务端按 `startedAt/endedAt` 计算 |
| 登录 | 密码明文比对、无 token | 加 hash + token + 过期策略 |
| `values` 参数校验 | 仅前端校验 | 服务端校验必填和参数定义；范围值异常值保留并标记偏离 |
| 图片/图标 | 以 base64 存在前端 state | 改为对象存储 + URL |
| 跳步审计 | 前端补写日志 | 服务端写审计表，不可删改 |
| 统计聚合 | 前端从 `taskHistory` 现算 | 服务端聚合接口（见下） |

**生产统计页**目前是前端从任务历史里现算的，涉及：四项经营指标、型号平均耗时、工位实时状态、参数偏离排行、按型号的工序耗时比重和近 12 个月产能趋势。
建议后端提供：`GET /stats/overview?from=&to=`、`GET /stats/trend?from=&to=`、`GET /stats/operators?from=&to=`、`GET /stats/parameter-deviations?from=&to=&model=`、`GET /stats/step-duration-share?from=&to=&model=`、`GET /stats/capacity-monthly?to=&months=12`；趋势按日期/月升序，排行按偏离次数降序。

## 5. 错误处理约定

- 现在所有用户可见提示都走 Element Plus 的 `ElMessage`，文案已产品化，**建议后端错误信息直接透出到同一位置**。
- 三档语义：`ElMessage.success`（成功）/ `.warning`（业务校验未通过）/ `.error`（系统或权限错误）。
- 建议 HTTP 约定：`200` 成功；`4xx` 业务错误（带可展示的 `message`）；`401` 跳登录；`5xx` 统一"服务异常，请稍后重试"。

## 6. 工位分段装配接口（v2）

| 前端动作 | 建议接口 | 要点 |
|---|---|---|
| 读取/新增/修改/删除工位配置 | `GET/POST/PUT/DELETE /workstations` | 工位使用最小空缺数字 ID，删除后可复用；保存名称与 `captureMode`。工位 1 为默认归属不可删除，删除其它工位时将当前工艺步骤迁移到工位 1，并拒绝删除被在制任务快照引用的工位。 |
| 扫码读取映射 | `GET /product-bindings/{productCode}` | 自动工位按产品编码返回最新型号、钢印号和该钢印号的在制任务。 |
| 手动建立或替换映射 | `PUT /steel-bindings/{steelNo}` | 保存钢印号、型号、当前产品编码、任务号；钢印号为全流程唯一编码。相同钢印号的新产品编码更新映射，不新建任务。 |
| 按钢印号恢复在制任务 | `GET /tasks?steelNo={steelNo}&status=in_progress` | 返回该钢印号的冻结快照、步骤日志及 `stationConfirmations`；服务端须支持多个钢印号任务并存。 |
| 确认工位汇总 | `POST /tasks/{taskId}/stations/{stationId}/confirm` | 保存本站全部参数汇总；后续工位据此解锁。 |
| 修改钢印号 | `POST /tasks/{taskId}/steel-no` | 服务端写审计并迁移钢印号主绑定及当前产品编码映射。 |
| 最终完成 | `POST /tasks/{taskId}/complete` | 保存全工位总汇总、各步骤的工位/操作人/参数/时间并结束任务；允许参数值为空，同时仅删除该钢印号的在制绑定与当前产品编码映射。 |
| 查询历史任务 | `GET /tasks?status=completed&productCode=&steelNo=` | 返回已归档任务及按工位、操作员分组的步骤明细，支持追溯查询。 |

后端必须以工艺快照内的 `stationId` 判断录入权限，并校验前置工位确认状态，不能依赖前端禁用控件。

工位内跳步仍使用 `POST /tasks/{taskId}/jump`，但请求目标必须属于当前工位；服务端应为向后跳的中间步骤写入普通/重要跳过审计。本站已完成步骤可用 `POST /tasks/{taskId}/steps` 再次提交以覆盖参数，并更新该步骤操作人和时间；跨工位步骤仅允许查看，不能借由跳转取得录入权限。
