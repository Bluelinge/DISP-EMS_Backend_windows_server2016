## 1. 顶级状态（`state`）

```js
{

  currentUserId: 'U-001',          // 当前登录人 id（个人信息弹窗据此取档案）

  productCode: '', steelNo: '',    // 工位端扫码结果

  activeTaskId: null,              // 当前打开的在制任务 id

  dicts:  [ /* 字典，见 3.8 */ ],
```

## 2. 枚举（**前后端必须对齐取值**）

| 枚举 | 取值 | 说明 |
|---|---|---|
| 人员角色 `person.role` | `操作员` / `管理员` / `超级管理员` | 登录端口映射：`操作员 → operator`，其余 → `admin` |
| 人员状态 `person.status` | `在岗` / 停用 | **只有「在岗」允许登录** |
| 工序是否重要 `step.importance` | `0` 普通 / `1` 重要工序 | 影响跳步日志的 `actionCode` |
| 日志动作码 `log.actionCode` | `0` 正常完成 / `1` 普通工序被跳过 / `2` 重要工序被跳过 | **`=== 0` 才算已完成**；`> 0` 进审计日志 |
| 参数类型 `parameter.type` | `0` 手动输入 / `1` 单选 / `2` 范围值 | `type:1` 时 `options[]` 有值且第一项为合格参考项；`type:2` 使用四段逗号范围参考值，旧两行格式兼容 |
| 参数类型缺失 `parameter.sourceTypeMissing` | `true` / `false` | 导入预检的错误依据（原 Excel 有 22 处缺失） |
| 任务状态 `task.status` | `进行中` / `已完成` | |
| 视频分类 `video.categoryId` | 分类实体 ID | 可指向一级或二级分类 |
| 字典状态 `dict.status` | `启用` / 停用 | |
| 字典类型 `dict.type` | `user_role` | 目前只有角色字典 |
| 投影元素类型 `element.type` | `icon` / `text` | |
| 投影元素绑定 `element.bindField` | `stepNo` / `stepTitle` / `none` | 见 3.6 |
| 确认表单项类型 | `0` 手动 / `1` 单选 / `2` 范围值 | 与 `parameter.type` 同构 |

## 3. 实体

### 3.1 人员 `person`
```js
{ id:'U-001', no:'OP-018', name:'李工', role:'操作员',
  dept:'总装车间', phone:'138****2018', status:'在岗', password:'123456' }
```
> `password` 是原型明文（仅演示）。接后端时**不要**把这个字段暴露给前端列表接口。

### 3.2 当前工艺摘要 `processRecord`
```js
{ id:'P-001', model:'DISPEN9243-40', title:'油压减振器总组装作业',
  version:'v1', sourceWorkbook:'…xlsx', sourceDocument:'…' }
```
`processFiles[]` 元素在此基础上多两个字段：`steps[]`（见 3.3）、`stepProjection{}`、`isDemo`。

### 3.3 工序 `step`
```js
{ stepNo: 1,                        // 工序号，数字，从 1 开始（**不补 0**）
  title: '穿戴防护用品',
  content: '按作业指导要求穿戴并检查防护用品。', // 可选操作步骤详情；旧工艺/快照缺省按空内容显示
  importance: 0,                    // 0 普通 / 1 重要工序
  videoName: 'NONE',                // 关联视频名；'NONE' 表示无
  parameters: [ /* 见下 */ ],
  sourceRow: 3                      // ※ 来自 Excel 的行号，导入预检用
}
```

工艺 Excel 使用可选“步骤内容”列保存操作步骤详情。列缺失或单元格为空时，`content` 为 `''`；新任务在创建时将该字段冻结到 `processSnapshot`，管理端后续修改不影响在制任务。操作端在右侧内容区显示步骤内容，在下方显示工艺参数。

`videoName` 保存视频资源的标准名称，由操作端查找并播放。Excel 导入会按名称唯一匹配视频资源，兼容常见视频扩展名、路径、首尾空格与大小写差异；旧工艺快照读取时也使用同一匹配规则，因此例如 `拧紧机` 可识别为视频资源 `拧紧机.mp4`。视频上传使用相同标准名防止重名，替换上传复用既有视频 `id` 并更新其名称、分类和会话媒体，已有 `videoName` 仍可被解析。任务启动后使用当时的 `processSnapshot`，因此在任务进行中才修改的视频绑定不会回写到该任务；需重新创建任务后生效。当前前端原型中的上传视频采用浏览器会话预览地址，刷新页面后需要重新上传，后端接入时应提供持久化的媒体地址。

**参数 `parameter`**
```js
{ index: 1,                         // 参数序号，**作为 values 字典的键**
  name: '组装温度( ℃)',
  type: 2,                          // 0 手动输入 / 1 单选 / 2 范围值
  referenceValue: '(>17),(=17),(=23),(<23)', // type=2：下限排除、下限包含、上限包含、上限排除
  options: [],                      // type=1 时的候选项数组，第一项为合格参考项
  sourceTypeMissing: false          // ※ Excel 里参数类型留空的标记
}
```
`type=1` 实例：
```js
{ index:3, name:'清洁度', type:1, referenceValue:'不得有明显落灰\n有明显落灰',
  options:['不得有明显落灰','有明显落灰'], sourceTypeMissing:false }
```

范围值新格式的四段固定为 `(>x),(=x),(=y),(<y)`，空边界写 `()`；例如 `(>30),(=30),(),(<70)` 表示 `30 <= value < 70`。超限或非数值会保留在步骤日志中，并在参数偏离排行中计为偏离。旧两行数值参考继续按闭区间兼容处理。手动输入按去除首尾空格后的文本精确匹配；单选仅第一项不偏离。

### 3.4 任务 `task`
```js
{ id: 'TASK-85973660',
  productCode: 'DISPEN9243-40-000126',
  steelNo: 'GY-240914-08',
  model: 'DISPEN9243-40',
  processId: 'P-001',
  operatorId: 'U-001', operatorName: '李工',

  status: '进行中',                  // → '已完成'
  currentStepIndex: 0,              // 当前工序在 activeSteps 里的下标
  startedAt: '2026-09-20T…Z',       // ISO 字符串
  endedAt: null,                    // 完成时写入
  durationSec: null,                // ⚠️ 原型由前端算，建议改后端算

  logs: { '1': { /* 见下 */ } },     // 工序号 → 日志（含工位及实际操作人）
  projection: { '1': { templateId, elements } },  // ★ 开始时冻结的投影配置
  processSnapshot: [ /* 工序数组 */ ],            // ★ 开始时冻结的工艺快照
  stationConfirmations: { '1': { stationId:1, stationName:'工位1', operatorName:'李工', confirmedAt:'…', items:[] } },
  steelNoAudit: [ { previousSteelNo:'GY-01', steelNo:'GY-02', stationId:1, operatorName:'李工', changedAt:'…' } ],
  productCodeAudit: [ { previousProductCode:'PC-01', productCode:'PC-02', stationId:4, operatorName:'李工', changedAt:'…' } ],
  completionForm: null              // 完成时写入 { savedAt, operatorName, items[] }
}
```

**步骤日志 `log`**
```js
{ stepNo: 1, title: '穿戴防护用品', stationId: 1, stationName: '工位1', operatorName: '李工',
  actionCode: 0,                    // 0 完成 / 1 跳过 / 2 重要工序跳过
  values: { 1:'21', 2:'55', 3:'不得有明显落灰' },  // 键 = parameter.index
  time: '2026-09-20T…Z' }
```

**完成确认表单 `completionForm.items[]`**
```js
[{ stepNo: 12, title: '点检测量设备',
   parameters: [ { ...parameter, operatorValue: '21' } ] }]
```

> ⭐ **两个"冻结"字段是核心业务承诺**：`processSnapshot` 与 `projection` 在任务开始时快照，
> 之后管理端编辑工艺/模板**不得**影响在制任务。后端务必保证同等隔离。

管理端“审计记录”中的工位操作明细以 `processSnapshot` 为行来源：每个工序一行，所属工位取 `step.stationId`，并与 `logs[stepNo]` 合并显示操作结果、操作人、时间和跳过原因；未生成日志的工序显示“未操作”。`task.steelNoAudit[]` 中的每次钢印号修改额外作为一行审计数据展示，包含操作员、冻结工位名称、修改时间、修改前编号和修改后编号。

### 3.5 在制任务集合与历史任务 `inProgressTasks` / `taskHistory[]`
`inProgressTasks` 以 `taskId` 保存多条并存任务，`steelBindings[steelNo].taskId` 是按钢印号恢复的主索引。`state.task` 只表示当前页面打开哪一条任务，不能被当作唯一在制任务来源。

`taskHistory[]` 结构同 `task`，额外含完成信息。`isDemo: true` 表示演示数据（接后端后应全部清理）。最终确认时深拷贝归档，因此此后新任务、工艺定义或钢印号暂存改变都不能污染历史记录。生产统计在没有真实已完成或进行中任务时，会在前端临时生成标记为 `isDemo` 的近 60 日完成任务、重复钢印号和在制任务数据，以覆盖“近7日”“近30日”及其紧邻上一周期的预览比较；这些数据不写入 `taskHistory[]`。

生产统计的完成件数按筛选期内已完成任务的唯一 `steelNo` 计数；“在修积压”按 `startedAt` 落入筛选期且状态为“进行中”的任务记录计数；一次合格率为筛选期内已完成且具有钢印号的任务记录中、钢印号仅出现一次的记录数 ÷ 完成任务记录数；总平均耗时为筛选期内已完成任务的 `durationSec` 平均值。“平均最长耗时型号”与“平均最佳耗时型号”按当前筛选期内每个型号的平均耗时计算，分别取最大值与最小值；卡片主数值显示平均耗时，最下方显示对应型号；无已完成任务时显示暂无完成数据。参数偏离排行读取已完成任务快照中的参数定义和 `logs[stepNo].values`，并按右上角所选型号过滤：范围值按四段边界校验，旧两行格式按闭区间兼容，其他手动值精确匹配，单选值只要位于 `options[]` 即合格。工序耗时按相邻实际完成日志时间差聚合；环形图明细按时长倒序，超过 4 个工序时其余项合并为“其他工序”，但总耗时不变。月产能按截至筛选结束日近 12 个自然月的唯一钢印号计数。已完成任务按完成时间筛选，在制任务按开工时间筛选；前四项指标均与紧邻、等长的上一周期比较。
用于：任务记录列表、按产品编码/钢印号查询、工位与操作员步骤追溯、审计日志、生产统计聚合。钢印号是任务和步骤进度的唯一键；`productCodeAudit` 保存中途替换的扫码产品编码。归档后应删除 `steelBindings[steelNo]` 及该任务当前的 `productBindings[productCode]`，两者只代表在制映射。

### 3.6 投影模板 `template` 与元素 `element`
```js
{ id:'T-001', name:'默认工序引导', isDefault:true,
  width:1920, height:1080,          // ★ 投影画布尺寸固定 1920×1080
  description:'系统默认模板，所有导入工艺步骤自动绑定',
  elements: [ /* 见下 */ ] }
```
```js
// 图标元素
{ id:'E-01', type:'icon', iconName:'文书', x:190, y:300, zIndex:1,
  scale:1, rotation:0, blink:false }
// 文本元素
{ id:'E-02', type:'text', text:'{{stepNo}}', bindField:'stepNo',
  x:460, y:286, fontSize:80, color:'#59C2DA', zIndex:2 }
```
- `x / y`：左上角坐标，**画布坐标系**（1920×1080）
- `zIndex`：层级；`scale / rotation / blink`：仅图标用（`blink` = 闪烁）
- `bindField`：`stepNo` / `stepTitle` / `none`。为 `none` 时仍会做**变量插值**（见下）

**投影模板变量**（写在 `text` 里，用 `{{变量}}` 形式，运行时替换）：
| 变量 | 含义 | 兜底值 |
|---|---|---|
| `{{stepNo}}` | 工序号（**投影里补 2 位，如 `01`**） | `01` |
| `{{stepTitle}}` | 工序标题 | `工序标题` |
| `{{progress}}` | 进度，形如 `12 / 35` | — |
| `{{model}}` | 产品型号 | 当前工艺 model |
| `{{steelNo}}` | 钢印编号 | — |
| `{{paramName1..3}}` | 第 1~3 个参数名 | `参数名称` |
| `{{paramValue1..3}}` | 第 1~3 个参数的**操作员录入值**，未录入时取 `referenceValue` | `参考值` |

> ⚠️ 待确认：`{{stepNo}}` 在投影里补 0（`01`），而管理端卡片数字已按规范**取消前导 0**。
> 若"不补 0"是全局数据规范，投影这里也要改（属产品决策，接手时请与设计确认）。

### 3.7 视频分类 `videoCategory`

```js
{ id:'VC-9243', name:'DISPEN9243-40', parentId:'VC-DAMPER', sortOrder:1 }
```

- `parentId: null` 为一级分类；非空表示所属一级分类，最多两级。
- 初始树：油压减振器 → `DISPEN9243-40` / `DISPEN9242-40` / `DISPEN9241-40` / `DISPEN9148-40` / 通用；其他为可直接归属视频的一级分类。
- 分类名称在同一级内唯一。删除分类前必须先删除二级分类，并清空该分类关联的视频。

### 3.8 视频素材 `video`
```js
{ id:'V-001', name:'减振器总成装配示范.mp4', categoryId:'VC-GENERAL',
  duration:'08:24', batch:'B-20260914-01', sessionPreview:false }
```
`sessionPreview` = 是否允许在作业会话中预览。

### 3.9 字典 `dict`
```js
{ type:'user_role', code:0, name:'操作员', status:'启用' }
```

### 3.10 投影图标素材 `icon`
- 内置：`iconNames = ['大屏','图片','文书','用户切换','退出']`，对应文件 `public/projector-icons/{name}.png`
- 自定义：`customIcons[] = { name, originalName, dataUrl }`（建议改为 URL）
- 访问入口：`iconUrl(name)` → 自定义优先，否则 `/projector-icons/{encodeURIComponent(name)}.png`
- 素材规格：256×256 PNG，**纯黑 + alpha**（无白色填充）；显示时按需用 CSS `filter: brightness(0) invert(1)` 反白

## 4. 持久化（原型专用，接后端后移除）

- localStorage 键名：**`disp-mes-ui-prototype-v1`**
- 读取：`loadState()` 与 `initialState()` 做**浅合并**（老数据缺字段时回落到初始值），所以新增字段一般不会报错
- 重置入口：登录页「重置演示」、管理端侧栏「重置演示数据」→ 均调 `reset()`
- **多窗口同步**：投影窗口与工位窗口靠 localStorage 共享状态（`syncFromStorage()` 重读）。接后端后改用同一份服务端数据 + 轮询/WS。

## 5. 工位分段装配（v2）

- `workstations[]`：可新增或删除的 `{ id, name, captureMode }` 列表；新增时使用最小空缺正整数 ID，因此删除工位后该编号可复用。`captureMode` 为 `manual`（扫码后手选型号、手填钢印）或 `auto`（按产品编码读取最新绑定）。初始工位 1 为 `manual`，其余初始工位为 `auto`；工位 1 是默认归属，不能删除。
- 手动录入时的产品型号候选固定为 `DISPEN9148-40`、`DISPEN9241-40`、`DISPEN9242-40`、`DISPEN9243-40`。
- `steelBindings[steelNo]`：`{ productCode, model, steelNo, taskId, updatedAt, updatedByStationId }`。钢印号是在制任务、步骤进度与交接的主索引和唯一编码。
- `productBindings[productCode]`：同结构的当前扫码映射，供自动工位扫码带出钢印号；它不是任务进度判断依据。手动工位以相同钢印号扫描不同产品编码时，更新主绑定的 `productCode` 并写入 `task.productCodeAudit[]`。
- `step.stationId` / `step.stationName`：现有工位编号及任务开始时冻结的工位名称；任务审计优先使用冻结名称，避免删除并复用同一编号后改写历史展示。导入文件没有“工位”列、工位值为空或编号已不存在时，步骤默认绑定工位 1。
- `task.stationConfirmations[stationId]`：本站汇总确认记录；后续工位只有所有前置工位已确认时才可录入。
- 操作端参数汇总的编辑权限由任务快照派生：本站所有步骤已有操作记录且前序工位已确认时可编辑本站汇总；所有汇总参数均填写后才可确认交接或提交任务。最终工位已确认本站、但任务仍为“进行中”时恢复为全产品“最终参数汇总”。非最终工位交接确认后参数冻结。
- 作业页进入开始作业后即显示“参数汇总”入口；当本站尚未完成且未确认、且全部前序工位已确认时（包含首工位），点击入口会将本站未完成步骤以“进入参数汇总”写入跳步审计、自动定位到本站最后一步，并直接打开可编辑、可确认的本站汇总。存在未交接前序工位时不跳步，提示“请先完成前序工位的全部步骤，并等待前序工位确认交接。”投影窗口使用固定命名窗口按任务 `id` 复用，开始作业时优先打开或切换至最新任务。
- `task.steelNoAudit[]`：钢印号修改审计，记录 `{ previousSteelNo, steelNo, stationId, stationName, operatorName, changedAt }`。任一站汇总页修改后，迁移钢印号主绑定及当前产品编码映射，供后续自动工位读取。
- `task.productCodeAudit[]`：产品编码替换审计。相同钢印号在新工位使用不同产品编码扫码时，仅替换当前产品编码映射，不重置任务进度。
- `liveStationTasks`：由 `inProgressTasks` 派生，不持久化。每条在制任务按冻结 `processSnapshot` 的工位顺序，归属首个未确认工位；全部确认但任务仍未完成时归属最终工位。旧任务没有快照时回退其 `processId` 对应工艺步骤。生产统计的 11 工位实时状态按该派生结果分组，鼠标悬停展示型号与钢印编号。
- 本原型的 `inProgressTasks`、钢印号主绑定、产品编码扫码映射、工位选择和工艺选择均存浏览器 localStorage；正式系统必须由服务端持久化，以支持跨设备工位交接和多钢印号并存。
